### 결과

**dev1 — 예상을 뒤집음.** 21분 시점 평가 완주율 98.8%. 라인 보상 `lr`은 좌표가 틀려 항상 0이었지만, "트랙 위 = 양수 / 탈선 = 0.001" 구조가 생존 보상으로 작동하고 속도 항이 1.7~3.0을 유도 → 사실상 "라인 무시, 트랙 안에서 속도 유지" 모델. **5/5 완주, 6.99~7.85 s.** 단, 조향 jump 11.1°/step, 풀조향 50%, **헤어핀 속도(2.36) > 직선(1.95) 역전** (곡률 인식 없음).

> 교훈: "의도대로 학습되는지는 로그로 확인한다." 그래프의 reward는 에피소드 합계라 스케일만으로 어떤 보상함수인지 알 수 있다.

**disc1-smooth** — 5/5 완주, 7.93~8.53 s. jump 11.7°, jump>20° **14%**(dev1 22%), 풀조향 **24%**(50%), 헤어핀 1.88 < 직선 1.99 (정상 순서). 다만 3.0 m/s action 사용 1%, ±30°/1.6 action이 18.6%로 최다 → 보수적 수렴.

**seg2-line** — 5/5이지만 7.73~10.07 s, 풀조향 **58%(최악)**. 연속 + 평활화 배율 0.5로는 지그재그를 못 잡음 → **이산이 구조적 해법임을 확인.** 제외.

(참고) 이날 밤 "차가 출발을 안 한다"는 문제는 **차량 기기 문제**로 확인·해결. 모델 문제 아님.

## 원칙 정리

1. **랩타임보다 완주 횟수를 먼저 본다.** 5회 평가에서 3회 미만이면 실전 2회 모두 실패할 수 있다
2. **한 번에 하나만 바꾼다.** clone은 가중치를 이어받으므로 action space 급변 금지
3. **시뮬 랩타임만으로 대표 모델을 정하지 않는다.** 실물 결과로 판단
4. **보상함수는 올리기 전에 실제 시뮬 waypoint로 수치 검증한다**
5. **학습 그래프 판단**: completion 정체 + reward만 상승 = 보상 해킹 / 상승 후 급락 = 과최적화(직전 체크포인트) / 코너 반복 탈선 = 목표속도 하향
