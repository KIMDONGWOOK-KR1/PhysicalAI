# 보상함수

모두 DeepRacer 콘솔에 그대로 붙여넣을 수 있는 단일 파일. flake8 0건.

| 파일 | 방식 | 사용 모델 | 비고 |
|---|---|---|---|
| **`reward_clone1.py`** ★ | `(progress/steps)*100 + 5·speed²·speed_score` × 조향 급변 배율 × 방향 정렬 배율 | disc1-smooth, **disc2-10act(최종)**, disc3-slots | 좌표 미사용(waypoints만). 전방 6wp 방향 변화로 곡률 → 목표속도 `clamp(3.0 − 0.02·curve, 1.7, 3.0)` |
| `reward_clone2.py` | clone1과 동일, 페널티 강화 (급변 0.5→0.7, 직선 과조향 0.3→0.5, 속도항 5→8) | disc2-v2 | 속도 변화 최저(0.22)였으나 실물 검증 전 대회 종료 |
| `reward_D_segment.py` | 사전 계산 레이싱 라인 24점 추종 + 구간별 목표속도 | dev1 | **좌표계 미보정** 상태로 학습됨. 라인 보상은 항상 0이었지만 생존 보상 구조로 5/5 완주 |
| `reward_D_segment_fixed.py` | 위 파일의 좌표를 시뮬 프레임으로 보정 (−(3.834, 2.758)) | — | 검증용 |
| `reward_D2_segment.py` | fixed + 허용폭 선형화, 조향 급변 배율, 매 스텝 pace 항, 완주 +10 | seg2-line | 연속 행동공간에서는 배율 0.5로 지그재그를 못 잡음 → 이산 전환 근거 |

## 설계 원칙

1. **승리 조건과 보상 정렬** — `progress/steps`가 주 항. 없으면 "느리게 정확히 가는" 모델로 수렴
2. **연속 보상** — 계단식 금지, 개선 방향이 항상 드러나야 함
3. **제약은 덧셈이 아닌 배율** — 특정 항만 따먹는 정책 차단
4. **탈선은 0이 아닌 1e-3** — 학습 신호 유지
5. **좌표 기반 보상은 올리기 전에 시뮬 waypoint(`data/sim_waypoints_57.npy`)로 라인이 트랙 안에 있는지 확인**

## 시뮬 환경 (reInvent2019_wide)

- waypoint 57개(0~56), 간격 0.289 m, track_len 16.598 m, 15 fps
- 시뮬 좌표 = `data/racing_line_110.csv` 좌표 − (3.834, 2.758), index는 ×57/110
